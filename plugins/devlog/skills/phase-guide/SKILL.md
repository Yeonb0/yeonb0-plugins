# devlog : Phase 분할과 종료 알림

개발일지는 Phase 단위로 쓰인다. Phase가 처음부터 정해져 있어야 "어디까지가 한 편인지"가 분명해지고, 끝나는 순간을 놓치지 않아야 기록이 신선할 때 글을 쓸 수 있다. 실행은 언제나 사용자가 한다. 이 스킬은 제안하고 알리기만 한다.

## 1. Phase 나누기 (프로젝트 시작 · 계획 단계)

- 작업을 사용자가 결과를 눈으로 확인할 수 있는 vertical slice로 나눈다. 한 Phase는 보통 며칠 ~ 2주 분량.
- 각 Phase에 `title`, `goal` (한 문장), `done` (확인 가능한 완료 기준 2 ~ 4개) 을 붙여 표로 제안한다.
- 사용자가 승인하거나 고치면, 프로젝트 저장소의 `.devlog/config.yml` 의 `phases` 에 기록한다. 설정 파일이 없으면 `references/config.md` 의 첫 실행 설정으로 먼저 만든다. 저장 방법은 `references/repo-access.md` 를 따른다 (로컬 git → `gh` → GitHub 커넥터).
- 커밋 메시지 : `chore(devlog): plan phases`
- 사용자가 Phase 기록을 원하지 않으면 강요하지 않는다.

## 2. Phase 종료 알림 (작업 중)

- `.devlog/config.yml` 이 있는 저장소에서 작업 중이면 `current_phase` 의 `done` 기준을 기억해 둔다.
- 대화 중 완료 기준이 모두 충족되었다고 판단되면 (테스트 통과, 기능 동작 확인, 사용자의 "됐다" 등) 한 번만 알린다 :

  > Phase N (`<title>`) 의 완료 기준이 모두 충족된 것 같습니다. `/devlog:publish` 로 개발일지 초안을 만들까요?

- 직접 실행하지 않는다. 사용자가 아직이라고 하면 같은 Phase에 대해 다시 묻지 않는다.

## 3. 세션 마무리

- 의미 있는 결정이 있었던 세션이 끝나 가면 (사용자가 마무리 인사를 하거나 작업을 정리할 때) `/devlog:note` 로 이번 세션의 결정과 이유를 남길지 한 번 묻는다.
- 단순 질문 · 짧은 수정만 있었던 세션에서는 묻지 않는다.
